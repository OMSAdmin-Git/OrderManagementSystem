🎯 2. Phased Test Cases

Test 1: Standalone Supplemental Forecast
🟢 Easiest #1

Target File: CSV_Example\03_CSV変換後\0602-260716.csv (Size: 1.3 KB)

Why test this first: 0602 is supplemental forecast data. By specification, it skips wash replacement and has zero dependencies on existing records. It offers the cleanest end-to-end test.

Execution Steps:

  1. Copy 0602-260716.csv into C:\ASTI\Order\Suzuki\.
  2. Run CLI: & ".\SUZUKI_SPIRITS_DATA_IMPORT\bin\Debug\SUZUKI_SPIRITS_DATA_IMPORT.exe" /batch
    (Or via Web UI: OrderImportStage.aspx 取込 → OrderImport.aspx 取込 & 保存)

Verification Points:

  • Staging table SUZUKI_SPIRITS_0602 updated to STATUS = 'REGISTERED'.
  • New orders inserted into ORDERS with CUSTOMER_CODE = '5455' and CUSTOMER_INFO_TYPE = '0602'.
  • Orders updated to STATUS = 'DUE_SET' with calculated SHIP_DATE and SHIP_SCHEDULED_DATE.
  • Audit records created in ORDER_HISTORY.
  • File moved to C:\ASTI\DATA\COMPLETED\...\0602-260716_*.csv.
Test 2: Main Monthly Forecast & Lead Time Calculation
🟢 Standalone

Target File: CSV_Example\03_CSV変換後\0600-260703.csv

Objective: Tests standard working-day delivery date calculation (ADD_WORKING_DAYS2 calendar 00001), unit/warehouse resolution, and Profit Center mapping from USRDEFFLDF.

Verification Points:

  • CUSTOMER_SETTING_ID resolved to the child Profit Center ID (from USRDEFFLDF.FUSRSTR1).
  • DUE_DATE correctly formatted and set to working date.
  • Records committed to ORDERS with ORDER_TYPE = 1 and STATUS = 'DUE_SET'.
Test 3: Forecast Wash Replacement (洗替加工)
🟡 Multi-Run

Target File: CSV_Example\03_CSV変換後\0600-260709.csv (Subsequent to Test 2)

Objective: Verify that importing a subsequent monthly forecast invalidates older active forecasts for matching items and reference dates.

Verification Points:

  • Prior 0600 records in ORDERS updated to STATUS = 'REPLACED' and ACTIVE_FLAG = 'N'.
  • New 0600 records become active with STATUS = 'DUE_SET'.
Test 4: Delivery Instruction & Forecast Consumption (納入指示消込)
🟡 Pair Test

Target File: CSV_Example\03_CSV変換後\0650-260701.csv

Objective: Verify destination conversion via SUZUKI_SPIRITS_CONVERSION_MST and automatic consumption of active 0600 forecasts.

Verification Points:

  • 0650 records inserted as ORDER_TYPE = 3, DEMAND_STATUS = 'O', DELIVERY_INSTR_FLAG = 'Y'.
  • SHIP_TO converted from order delivery code to plan delivery code via conversion master.
  • Matching active 0600 forecast DEMAND_QTY consumed / reduced.
  • Fully consumed forecasts updated to STATUS = 'RECONCILED' and ACTIVE_FLAG = 'N'.
Test 5: Special Modifier Adjustments (0630, 663N, 663S)
🔴 Modifiers

Objective: Modifier files never insert new orders; they locate an existing order in ORDERS_STAGE or master ORDERS and adjust its attributes.

Sub-case Modifier File Target Record Expected Adjustment
5-A 0630-260715.csv Matching 0600 forecast DEMAND_QTY increased by 0630.ORDER_QTY
5-B 663N-260708.csv Matching 6624 firm order DUE_DATE shifted to new working date
5-C 663S-260703.csv Matching 6624 firm order DEMAND_QTY updated to 663S.ORDER_QTY

🔍 3. Database Verification Queries

Run these queries in SQL Developer / SQL*Plus on localhost to confirm the results:

1. Verify Staging Table Records (SUZUKI_SPIRITS_*)

SELECT '0602' AS info_code, status, active_flag, COUNT(*) FROM suzuki_spirits_0602 GROUP BY status, active_flag
UNION ALL
SELECT '0600', status, active_flag, COUNT(*) FROM suzuki_spirits_0600and0630 WHERE info_type_code = '0600' GROUP BY status, active_flag
UNION ALL
SELECT '0650', status, active_flag, COUNT(*) FROM suzuki_spirits_0650 GROUP BY status, active_flag;

2. Verify Master Orders (ORDERS)

SELECT 
    order_id,
    customer_code,
    customer_setting_id,
    customer_info_type,
    order_type,
    item_no,
    ship_to,
    demand_qty,
    order_date,
    due_date,
    ship_date,
    ship_scheduled_date,
    status,
    active_flag,
    updated_at
FROM orders 
WHERE customer_code = '5455'
ORDER BY updated_at DESC;

3. Verify Order History Audit Trail (ORDER_HISTORY)

SELECT history_id, order_id, customer_code, status, created_at, created_user_id, created_pg_id
FROM order_history
WHERE customer_code = '5455'
ORDER BY history_id DESC;
